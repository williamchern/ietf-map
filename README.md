# IETF Atlas — 文稿地图

把你在意的 IETF 草案与 RFC 钉到它所属的工作组 / 研究组上，形成一张**可度量知识缺口**的活地图。

> ⚠️ 本应用是**第三方非官方工具**，与 IETF、IETF Trust、IETF LLC 无任何隶属或背书关系。
> 数据来自 [IETF Datatracker](https://datatracker.ietf.org/api/) 公开 API；不镜像文档正文，仅展示元数据与摘要节选并链接回原文。

当前快照：**1614 个组织实体 · 20688 份文稿 · 45.4 万条引用与演进关系**（覆盖全部 WG / RG / Area，含已关闭组）。

## 目录

```
app/                 可安装的 PWA 前端
  index.html
  manifest.webmanifest
  sw.js              离线缓存（外壳 network-first，快照与 /api 走网络）
  assets/            原生 ES Modules，无构建链
  data/snapshot.json 构建期生成的 IETF 数据快照
  data/layout.json   图谱的静态坐标（离线算好，运行时只读）
  assets/offline.js  离线正文：按版本下载、存 IndexedDB、应用内阅读
server.py            静态托管 + /api/live 同源代理（转发 Datatracker，解决 CORS）
launcher.py          托管平台用：端口没开时重试、探针断连不退出，起来后打一行就绪日志
scripts/
  fetch.py           从 Datatracker 拉取草案/组/关系 → scripts/out/*.json
  fetch_rfcs.py      拉取全部 RFC → scripts/out/rfcs.json（可低频更新）
  pack.py            合并压缩 → app/data/snapshot.json
  layout.py          图谱静态坐标（graphviz dot 求层次）→ app/data/layout.json
docs/
  PRODUCT_DESIGN.md  产品定位与取舍
  LEGAL.md           法律风险清单与措施
  DEPLOY.md          域名、发布、定时刷新
```

## 快速开始

```bash
PORT=8080 python3 server.py   # http://localhost:8080
python3 launcher.py           # 托管平台用（$PORT 由平台注入）
```

> 必须用 `server.py` 而不是纯静态服务器：前端需要 `/api/live/*` 同源代理，
> 浏览器的跨域限制不允许直连 `datatracker.ietf.org`。

## 核心功能

信息架构刻意做窄：**一个问题一个入口**。图谱页只回答一个问题——**这个技术领域里，谁建立在谁之上**；其余结论（缺口、待读、组归属）交给清单。

| 页面 | 说明 |
|---|---|
| **图谱** | 一幅**静态分层图**：一行是一层，最底下一行是这个领域的地基，越往上越是建在它之上的新工作；箭头一律从引用方指向被引用方。坐标离线算好（`graphviz dot` → `app/data/layout.json`），刷新、放大、全屏都不变形。点一个节点只做"聚焦"（无关节点淡出、旁边/下方列出它依赖谁 / 谁依赖它），**绝不重排**。右侧「全屏」是真全屏：页眉页脚一起收起，Esc 退出；全屏（以及手机上）**图在上、说明在下**，说明区自己滚，不跟图抢宽度。下拉里只列**你收藏的草案所在的工作组**——全站的公共组不列。 |
| **收藏库** | 按工作组 / 研究组自动归类，每组标 **已收 / 组内总数**，一眼看出哪块有遗漏；另列"关注了但一份没收"的空心组。表格只留四列（文稿 / 标题·笔记 / 被引 / 管理），名字占最宽，窄屏收起次要列。 |
| **诊断** | 一张按优先级排的**待办清单**：① 你引用了但没读（已滤掉 RFC 2119 那类样板规范）② 组里有你没收 ③ 已过期 / 被替代 ④ 关注了但没读的组。没有评分、报告、导出——那些是给别人看的。 |
| **离线阅读** | 收藏库里**点文稿名**（或右边「管理」）打开同一张版本面板：挑版本，然后**下载到本机**（断网能读）、**在线看**（不占空间，需联网）或**读本机副本**。正文来自 `rfc-editor.org` / `ietf.org/archive`，只去掉每页重复的页眉页脚，内容一字不改。版本面板先用本地快照**秒出**版本表，再后台向 Datatracker 核对有没有新版。顶部「离线管理」可查占用、逐份删、一键清空；删收藏时会问「只移除收藏 / 连同离线一起删」。 |
| **配置 / 日志 / 帮助** | 域名前缀（可改）、主题、LLM 端点、备份导入导出；本地操作日志；使用说明与法律声明。 |
| **顶栏** | 左上角是**视图下拉**（图谱 / 收藏库 / 诊断 / 配置 / 日志 / 帮助），点一下竖排展开，不用在横排标题里逐个找。 |

### 关于"关系"的口径

| 概念 | 定义 | 为什么要区分 |
|---|---|---|
| **直接引用** | 收藏的文稿之间在 Datatracker 里有真实引用记录（`refnorm` 规范 / `refinfo` 信息性） | 硬依赖。看结论前必须读过 |
| **间接相连** | 没有直接引用，但被同一份第三方文稿（多为 RFC）共同引用 | 同一技术前提。往往是理解它们的关键缺环 |
| **跨组依赖** | 跨工作组的引用方向聚合到组 | IETF 的知识分工在组这一级，不在单篇 |

> 被 800 份以上文稿引用的（RFC 2119、RFC 8174 那一类）判为**样板规范**，不进入"间接相连"，只计数——否则任何两份文稿都会"有关系"，结论就没意义了。

## 技术要点

- **两级数据源**：静态快照（全量，供图谱与缺口分析）+ 实时回源（单条精确查询，`/api/live/*` 代理到 Datatracker）。
  快照里没有的草案——包括刚发布的新稿——添加时会自动实时补上，并把元数据一起存进本地。
- **关系解读（可选 LLM）**：把已抓取的真实引用边喂给模型做归纳，**每条结论必须携带证据编号**，
  校验不通过的直接丢弃并计数。未配置 Key 时自动降级为本地统计归纳，功能不依赖外部服务。
- **local-first**：收藏、笔记、日志全部存 IndexedDB，无账号、不收集个人信息。
- **零依赖**：无框架、无打包器，`app/` 目录直接扔到任何静态托管即可。
- **离线正文**：`server.py` 的 `/api/docfile` 只做**白名单原样转发**（`rfc-editor.org` / `ietf.org/archive`，名字与版本号正则校验，12MB 上限），
  正文存进 IndexedDB 的 `offline` store；不上传、不改写，删收藏时可一并清理。
- **图谱自研（v0.5 起改为静态分层）**：布局离线算（`scripts/layout.py` 用 `graphviz dot` 求层次，再在浏览器里排成"层 = 行"的网格），运行时约 300 行原生 SVG，只按坐标画点与箭头。
  不再用**力导向**——它的每一次交互都会重排，用户看到的是"点一下全乱了"；分层图的形状恒定，箭头方向就是依赖方向。

## 域名
