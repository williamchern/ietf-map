# IETF 内容使用的法律风险与应对措施

> 本文是项目约束「识别引用 IETF 内容的法律风险，给出措施」的落地文档。不构成法律意见；上线前如涉及商业化，请咨询专业律师。

## 一、风险清单

| # | 风险 | 说明 | 等级 |
|---|---|---|---|
| R1 | **版权（文档正文）** | IETF 文档（I-D / RFC）版权归作者与 IETF Trust，受 **BCP 78 / TLP**（Trust Legal Provisions）约束。早期 RFC（BCP 78 之前）还有单独的版权声明，条款各异。整篇复制、镜像、再分发需满足 TLP 条件（署名、Copyright Notice、许可文本、不加修改等）。 | 高 |
| R2 | **摘要/节选的使用** | Datatracker 提供的 abstract 属文档内容的一部分。截断引用 + 明确标注 + 链接回原文，一般构成**合理引用 / fair use**，但批量、完整地重新分发整库摘要仍有风险。 | 中 |
| R3 | **商标** | "IETF" 及 IETF 标识、菱形标志为相关主体商标。"ietfmap.app" 中含 "ietf" 字样，存在**混淆可能性**——这是本项目最大的法律暴露点。 | 高 |
| R4 | **暗示官方关系** | 若观感、命名、配色模仿 Datatracker，可能构成**虚假关联**（false association / passing off）。 | 中 |
| R5 | **BCP 78 § 4「IETF 名称使用」** | TLP 明确限制以 IETF 名义使用其名称与标识，尤其禁止造成"背书"印象。 | 中 |
| R6 | **API 使用条款** | Datatracker API 为公开数据接口，但高频抓取可能违反可接受使用政策，或因负载被判为滥用。 | 低 |
| R7 | **数据处理（隐私）** | 本应用无账号、无追踪，风险极低；若加云同步，需重估 GDPR / 个保法。 | 低 |
| R8 | **输出物的再分发** | 导出的 Markdown 报告含标题、摘要节选，若被第三方转载，责任链条需切割。 | 中 |

## 二、应对措施（已落地 / 待执行）

### 已落地（代码中可直接核对）

1. **不镜像正文**：快照只存元数据 + 摘要节选（≤900 字符，`scripts/fetch.py` 中 `d["abstract"][:900]`），从不缓存 HTML/PDF/TXT 全文。
2. **明确链接回官方**：每份文稿都以 `https://datatracker.ietf.org/doc/<name>/` 外链形式提供（`data.js: DOC_URL`）。
3. **常驻非官方声明**：
   - 页脚：`本站为第三方视图，与 IETF、IETF Trust、IETF LLC 无关联，未获其背书`
   - 顶部导航：`Unofficial` 徽标（不可关闭）
   - `#/about` 独立法律页，含版权、商标、免责、联络四段
4. **不使用官方视觉资产**：应用图标为自绘节点图，配色取自 GitHub 设计系统，未使用 IETF Logo、菱形标志、Datatracker 字体与布局。
5. **指标免责**："被引次数""覆盖度评分""孤儿草案"等在 `#/about` 与 `#/help` 中明确标注为**本站启发式指标，非 IETF 官方评价**。
6. **报告自带来源声明**：每份导出的报告末尾附 `本报告由 IETF Atlas 基于 IETF Datatracker 公开数据自动生成…原文以 ietf.org 为准`。
7. **API 礼仪**：构建期每日一次、`User-Agent: ietf-atlas-build/1.0`、支持 gzip、分页 limit=1000，单次约 5–8 分钟完成。

### 待执行（上线前）

8. **域名决策**：`ietfmap.app` 属描述性使用，但风险不为零。若收到异议，5 个工作日内迁移至中性名（预备案：`draftatlas.app`、`wgatlas.app`、`ietf-atlas.dev`），代码内根域在「配置」页可一处修改。
9. **书面联络**：上线后向 IETF Trust（`trustee@ietf.org`）与 IETF LLC 发一封简短告知邮件，说明用途、数据来源、不镜像正文、无商业目的。**主动告知比事后被通知成本低得多。**
10. **DMCA / 下架流程**：about 页承诺"收到异议 7 日内响应"，并保留一键下线开关（静态站点下架即删除部署）。
11. **不接广告、不收费**：避免把"使用他人公开数据"直接变现，这是商业化路径上最容易触发争议的环节。

## 三、可选的"低风险改名"方案

若希望把商标风险压到最低，把 `ietf` 从域名中移出：

| 候选 | 风险 | 可记忆性 |
|---|---|---|
| `atlas.ietfmap.app` | 中（含 ietf） | 高 ✅ |
| `rfcbuild.dev` / `draftgraph.dev` | 低 | 中 |
| `stdatlas.app` | 低 | 中 |
| `wg-atlas.dev` | 低（wg 为通用缩写） | 中 |

结论：**先用 `atlas.ietfmap.app` 上线，保留切换通道**。它在产品语义上最准确，且只要不模仿官方视觉、常驻免责声明，实践中的风险可控。

## 四、内容再分发矩阵

| 场景 | 允许 | 条件 |
|---|---|---|
| 站内展示标题/编号/状态/日期 | ✅ | 无需许可（事实性数据） |
| 站内展示摘要节选 | ✅ | ≤900 字、标注"节选"、链接原文 |
| 用户导出个人报告（含节选） | ✅ | 仅个人使用，报告内嵌来源声明 |
| 对外提供全量摘要 API | ❌ | 需评估 TLP，或改为仅返回标题与链接 |
| 镜像 PDF/HTML 全文 | ❌ | 明确禁止 |
| 付费墙后供内容 | ❌ | 不建议 |
